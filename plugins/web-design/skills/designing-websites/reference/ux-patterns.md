## NN/g 10 項啟發式（審查用）

關鍵流程逐項檢查，每個問題記下畫面與修法（[NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/)）。第 2、4、6、8 項從靜態畫面就看得出來，方向稿階段先看一次；其餘在展開後看完整流程：

1. **系統狀態可見**：送出、載入、儲存、產生中都有回饋；長工作顯示進度與可取消。
2. **貼近真實世界**：用使用者的詞（機關用語、業界用語），不用工程術語。
3. **使用者可控制**：可取消、可復原（刪除給「復原」比確認框更好）、可離開流程。
4. **一致性與標準**：同一動作同一樣式與位置；遵守平台慣例（Logo 回首頁、右上帳號）。
5. **預防錯誤**：限制輸入格式、危險動作要確認、預設值安全。
6. **辨識勝於回憶**：選項看得到，不要求記住前一頁的資訊。
7. **彈性與效率**：常用者有捷徑（快捷鍵、最近使用、批次操作）。
8. **美感與極簡**：每個元素都要有用途；次要資訊收起來。
9. **協助辨識與修復錯誤**：錯誤說明原因與解法，不道歉、不含糊。
10. **說明與文件**：需要時在情境中提供（欄位說明、空狀態引導）。

## 資訊分層

流程第 3 步用。先決定每個功能什麼時候看得到，再做方向稿。

| 層 | 意思 | 常見形式 |
|---|---|---|
| 一直在 | 第一屏不用操作就看得到 | 主要任務的內容與它的主要動作 |
| 就在旁邊 | 第一屏看得到，但視覺上退後 | 次要按鈕、頂列項目、內容旁的對照資訊 |
| 一行收著 | 只佔一行，按了原地展開 | 收合列（「附件（3）」）、摘要列、小選單 |
| 按了才有 | 第一屏只留入口 | 抽屜、對話框、分頁、另一頁 |

怎麼分（依 NN/g〈[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)〉：常用的功能要一開始就看得到，進階或少用的延後，而且怎麼進到下一層要很明顯）：

- **使用頻率**：每次任務都用到 → 一直在；多數任務會用 → 就在旁邊；偶爾用 → 一行收著；少用、設定類、一次性 → 按了才有。改版有使用統計就用統計；沒有就從任務推，並在表上標「推測」。
- **藏起來的代價**：要邊做邊對照的東西（例：報修單與它的處理進度）不要收到看不見的地方；會影響結果的設定（例：篩選的日期範圍）收起來時，至少留一行顯示目前的值；狀態、錯誤、進行中的工作不能收。
- **入口**：收起來的東西要有看得到、寫明內容的入口，能附數量更好（「留言（12）」）。不靠滑鼠移上去才出現，不用只寫「更多」的入口。
- **第一層寧少**：要把一項放進「一直在」，要說得出它每次任務都用到。

規則：

- 一個畫面一個主要動作。
- 「功能不能少」指每個功能都找得到，不是都在第一層。
- 原型的版面結構（幾欄、什麼同時攤開）不是需求，除非使用者說是。
- 每一項收起來的代價寫出來：誰會多按一下、寬螢幕時要不要改成常駐。

分層表的格式（給使用者確認，定案後放進 DESIGN-SYSTEM.md）：

| 功能 | 原型裡的位置 | 層 | 形式 | 理由與代價 |
|---|---|---|---|---|
| 送出報修 | 首頁中間 | 一直在 | 表單＋主要按鈕 | 每次任務都用 |
| 歷史報修單 | 左欄常駐 | 按了才有 | 左側抽屜，頂列入口 | 一次只查幾次（推測）；常查舊單的人多按一下 |

## 圖示

圖示是介面的一部分，在方向稿階段就決定，不是最後才補的素材。

- **作用**：幫人掃視與辨認操作。不是代替文字，也不是減少資訊量的手段；資訊量靠〈資訊分層〉處理，圖示負責讓留下來的東西好找。
- **要有一直看得到的文字標籤**，不靠滑鼠移上去才出現（觸控裝置沒有滑鼠移入）。依據 NN/g〈[Icon Usability](https://www.nngroup.com/articles/icon-usability/)〉：接近人人都懂的圖示只有首頁、列印、搜尋幾個，其餘都要靠標籤說明它在這裡的意思。
- **純圖示按鈕**只在兩種情況用：上述幾個普遍認得的圖示（關閉對話框的 ✕ 不在該文所列，是業界慣例，也可以）；或旁邊已經有文字當它的標籤（例：「這篇說明有幫助嗎？」後面的讚與倒讚）。兩種都要有 `aria-label` 與 tooltip。
- **該放**：導覽與頂列、每個畫面的主要動作、工具列上重複出現的操作（複製、下載、釘選）、狀態與提醒（搭配文字，不只靠顏色）、上傳區、用來分辨類型的地方（檔案類型、通知種類）。
- **不該放**：內文與標題裡、長清單每一列都重複同一個圖示（沒有資訊）、純裝飾。
- **一致**：同一個意思用同一個圖示，風格與筆畫粗細一致；顏色跟著文字（`currentColor`），大小跟著字級；裝飾性的圖示加 `aria-hidden="true"`，由旁邊的文字當名稱。
- 表情符號不當介面圖示：各平台長相不同，也沒辦法跟著文字顏色。
- 工具型介面的頂列與主要操作沒有圖示時，要在方向稿說明寫理由。來源、打包方式與授權見 assets.md。

## 頁型重點

下面是可用性研究的結論，管的是好不好用，不管長相；版型、風格、放不放圖由方向決定。

- **Landing／官網首頁**：首屏看得出這是什麼、能做什麼；按鈕文字寫明按了會怎樣；什麼都強調等於沒強調（[NN/g](https://www.nngroup.com/articles/homepage-design-principles/)）。行動版首屏也要看得到主要按鈕。
- **表單**：單欄排列，相關的短欄位（縣市與郵遞區號、年月日）可同列（[Baymard](https://baymard.com/blog/avoid-multi-column-forms)）；標籤多半放欄位上方，很長的桌機表單可放左側（[NN/g](https://www.nngroup.com/articles/web-form-design/)）；必填欄位都標出來，選填也標更好（[NN/g](https://www.nngroup.com/articles/required-fields/)、[Baymard](https://baymard.com/blog/required-optional-form-fields)）；錯誤多半等離開欄位後才顯示，新密碼這類複雜輸入可以邊打邊驗（[NN/g](https://www.nngroup.com/articles/errors-forms-design-guidelines/)）；送出按鈕寫出結果（「建立帳號」而非「送出」）。
- **儀表板／工具型產品**：最常用的任務放在第一層，其餘照〈資訊分層〉收；分組先試留白，不夠再加框（[NN/g](https://www.nngroup.com/articles/common-region/)）；空狀態說明下一步；表格支援排序、篩選、欄寬。
- **電商**：商品頁、搜尋、購物車、結帳依 [Baymard](https://baymard.com/research/methodology) 的研究（例如允許訪客結帳、運費提早揭露、商品圖可放大）。做電商時上網查 Baymard 對應主題的公開文章。
- **內容／文件**：閱讀欄寬以約 40 個中文字為參考值（DADS；WCAG 1.4.8 是 AAA），有摘要、標題幫助閱讀時可以更寬；目錄可跳轉；標題層級清楚。

## 中文排版

依日本數位廳設計系統 DADS（[字體規範](https://design.digital.go.jp/dads/foundations/typography/)），中日文相近、可直接借用：

- 內文與 UI **16px 以上**；**低於 14px 原則上不用**，14px 只用在頁尾等附屬資訊。
- 內文行高 **至少 1.5**，長文建議 1.7 左右；CSS 用無單位數值。
- 字距隨字級調整：小字 `0.02em`，大標題 `0` 或 `0.01em`。
- 字型：黑體、明體各管什麼由方向決定，寫進規範。數字欄位用 `tabular-nums`。
- 中文字型多半沒有真正的斜體，是電腦硬拉斜的；強調優先用字重、顏色或著重號。
- 標點用全形；中英文之間的空格依專案文案規範統一。

## 元件與互動慣例

- 主要按鈕一個畫面一個；危險、難復原的動作要和一般按鈕分得出來，不只靠紅色（[GOV.UK](https://design-system.service.gov.uk/components/button/)）。
- 圖示搭配一直看得到的文字；純圖示按鈕的條件見〈圖示〉。
- 動效要有目的；時長約 100～500ms，越常出現的越短（[NN/g](https://www.nngroup.com/articles/animation-duration/)）；自動播放超過 5 秒的要能暫停（WCAG 2.2.2）；遵守 `prefers-reduced-motion`。
- 深色模式：每個 token 有深色值，不是直接反轉；越上層的面越亮（[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/dark-mode)）。
- RWD：行動優先；斷點處理頁面骨架，元件內部用 container queries。
