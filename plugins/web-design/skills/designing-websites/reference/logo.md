## 流程

```
Logo 進度：
- [ ] 1. Brief：用 AskUserQuestion 收名稱、一句話品牌概念、要傳達的 3 個形容詞、使用場合（網站、印刷、招牌、App）、不要的元素
- [ ] 2. 3 個概念，各一個 SVG（圖形＋字標組合）給使用者挑
- [ ] 3. 選定後迭代 1～2 輪
- [ ] 4. 黑白測試、16px 測試、深淺底測試
- [ ] 5. Claude 自己做撞名與近似檢查（見最後一節），結果寫進交付說明
- [ ] 6. 匯出交付檔
```

概念發想同 distinctive-design.md：從品牌意涵與題材取意象，3 個概念走不同路線（例：具象圖形、抽象幾何、純字標）。

## 繪製規則

- `viewBox` 用方形（例 `0 0 512 512`），圖形置中，四周留約 10% 安全邊距；橫式組合版另做一個 `viewBox`。
- 只用基本形狀與路徑，筆畫粗細一致；文字轉成路徑（不依賴使用者電腦的字型），或在 SVG 內只用自架字型時註明。
- 顏色 1～3 色，用 CSS 變數或 `currentColor` 方便出單色版。
- 不放漸層、陰影、細到 16px 會消失的細節；不使用圖庫照片或他人圖形。
- 中文字標：字數多時只用圖形或縮寫做 favicon。

## 測試

逐項做完並截圖給使用者：

1. **黑白**：純黑、純白（無灰階）各一版仍可辨識。只靠顏色辨識的設計要重做。
2. **小尺寸**：16×16、32×32 仍看得出輪廓。看不出就為 favicon 另做簡化版（保留核心圖形，拿掉字與細線）。
3. **深淺底**：白底、品牌深色底、照片底各放一次；需要時做反白版。
4. **對比**：logo 若兼作按鈕或連結的圖示，對背景至少 3:1（`contrast.py` 的 `ui` 類型）。

## 交付清單

用本 skill 的 `scripts/export_logo.py`（完整路徑見 SKILL.md〈腳本〉）產出點陣檔：`export_logo.py logo.svg <輸出資料夾> --favicon favicon.svg`；SVG 版本手動整理：

```
logo/
├── logo.svg                 母檔（全彩）
├── logo-horizontal.svg      橫式組合版（需要時）
├── logo-black.svg           單色黑
├── logo-white.svg           單色白（反白）
├── favicon.svg              簡化版；可內嵌 @media (prefers-color-scheme: dark) 跟隨深色模式
├── favicon.ico              16/32/48（腳本產出）
├── apple-touch-icon.png     180×180，不透明底（腳本產出）
├── logo-512.png … logo-16.png（腳本產出）
└── LOGO-GUIDE.md            最小尺寸、安全邊距、色值、錯誤用法（拉伸、改色、加特效）
```

HTML：

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
```

## 商標檢索

由 Claude 自己做，不要求使用者去查，也不因此停下流程。提概念前先查名稱，定案後再查圖形。

查詢用本 skill 的 `scripts/tipo_search.mjs`（完整路徑見 SKILL.md〈腳本〉），它用外掛自帶的 Playwright 操作經濟部智慧財產局[商標檢索系統](https://cloud.tipo.gov.tw/S282/S282WV1)：

```bash
node tipo_search.mjs text "<品牌名>" <輸出資料夾> --class 030,043     # 文字近似
node tipo_search.mjs image <logo.png> <輸出資料夾> --class 030,043   # 以圖找圖（PNG／JPG，≤ 5MB）
```

`--class` 填實際營業項目的商品服務類別（尼斯分類，例：咖啡 030、餐飲 043、零售 035、軟體 009／042）。

1. **名稱**：只查有識別性的字詞（「山嵐咖啡」查「山嵐」，不要帶「咖啡」這種通用詞，否則結果會被通用詞淹沒）；主要字詞、英文名各查一次。另外上網搜尋同名品牌加產業關鍵字。
2. **圖形**：定案 logo 匯出 PNG 後查以圖找圖。
3. **讀結果**：讀 `result.json`（依相近程度排序的案件：名稱、申請號、狀態、是否有效、類別、申請人），用 Read 看 `result.png` 比對前幾筆的圖樣。只把「有效的註冊案或申請中案件、同類別、名稱或圖形明顯相近」的列為風險。
4. **有明顯相近的**：直接調整設計避開（換意象、改輪廓或字形）再查一次，並告訴使用者查到哪幾件、為什麼改。
5. **交付說明寫清楚**：查了哪些字詞與圖、類別、查詢日期、總筆數、列為風險的案件。

腳本結束碼 3 代表查詢失敗（網路異常、系統維護）：這不是「查無近似」，重試一次；仍失敗就在交付說明照實寫「未查到」與原因，不要求使用者代查。

檢查結果是降低撞名風險，不是法律意見，是否近似最終由智慧局認定；交付說明裡寫一句即可。使用者說不用查（內部系統、原型）就跳過並註明。

做法依據：[智慧局商標 FAQ 2.2.38](https://www.tipo.gov.tw/tw/trademarks/568-7691.html)。
