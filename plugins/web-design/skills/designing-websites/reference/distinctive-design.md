## 特色從哪裡來

依序想，前一層有答案才動下一層：

1. **資訊安排**：這個畫面先給人看什麼、什麼收起來、主要動作在哪（第 3 步的分層表）。同類產品都全攤開時，「第一屏只做一件事」本身就是特色。
2. **排版**：層級、欄寬、字型分工（黑體與明體各管什麼）、留白、對齊。
3. **色彩**：從品牌一手資料或題材取色，每個顏色有固定的意思。
4. **圖形語彙**：線、框、面、圖樣、插圖。放最後，也可以沒有。

「像 AI 做的」設計多半把順序倒過來：先挑一個搶眼的外觀，再把所有內容塞進去。

## 概念發想：取原則，不取外觀

1. 列出使用者世界裡的 **5～7 個實物或意象**：他們每天看的文件、工具、場所、產品本身。
2. 對每一個問「它為什麼好用」，寫成一條可以搬到螢幕上的**原則**，不是記下它長什麼樣子：

   | 意象 | 取外觀（題材扮裝，不要） | 取原則（要） |
   |---|---|---|
   | 機場航班看板 | 黑底黃字、翻牌字效 | 每一列欄位順序固定，狀態欄只用幾個詞 → 同一種資訊每次都在同一個位置，狀態用固定詞彙 |
   | 食譜卡 | 牛皮紙底、手寫字 | 材料先列齊、步驟編號、一步只做一件事 → 先列需要準備的東西，操作分步驟，一個步驟一個動作 |
   | 地圖圖例 | 等高線紋路、羅盤裝飾 | 符號少、圖例固定在角落、放大才出現細節 → 記號種類少、說明放固定位置、細節按了才展開 |

3. 加上**一手品牌資料**：標誌設計說明、色彩意義、機關或品牌歷史。
4. 每個方向寫一句話概念，講的是**畫面怎麼安排**，不是看起來像什麼。概念借了實物時，每個借來的元素要說得出它取代了什麼或標示了什麼（例：用面的明暗分層取代分隔線、記號兼作狀態標示）；說不出來就是題材扮裝，重寫。
5. 2～3 個方向的資訊安排要不同（例：一個只留主要任務、其餘按了才有；一個把對照資料放在內容旁邊），不要只換顏色與字型。

**題材扮裝**為什麼不行：沒有功能的外觀（紋理、裝飾框、刻度）只佔位置，而且容易落在某個現成風格上（粗框＝新粗野主義、紙紋與印章圖樣＝擬物）。外觀與題材有關，不代表設計從題材長出來；判斷看它有沒有功能，不看它借自哪個實物。使用者指定的風格與質感（例：手繪、蠟筆）、同類產品普遍有的主視覺與插圖不算扮裝，照做。

上表只示範推導方式。題目剛好相近時也不要直接拿來用；第一個想到的概念先放一邊，它通常也是別人第一個想到的；發散比較後它仍勝出可以用，在方向稿說明寫出比較過什麼。

## 換題測試

每個方向截圖後、給人看之前做，三題的答案寫進方向稿說明。這是診斷：不過的題目指出要回〈特色從哪裡來〉哪一層重想，不是加東西修飾。

1. **換題**：把題目換成銀行、學校、物流公司，列出必須跟著改的決定，分兩類：**版面**（什麼放在哪、怎麼排，因為這個題目的內容或工作方式才成立）與**身份**（顏色各代表什麼、字型怎麼分工、用詞、記號，出自這個品牌或題材的一手資料）。兩類合計寫得出兩條以上並說明原因才過；只換品牌名與主色就成立的不算。工具型產品的版面跟著同類產品的慣例走是對的（[NN/g：使用者大部分時間在用別的網站](https://www.nngroup.com/articles/end-of-web-design/)），特色可以全在身份那一類。
2. **卸妝**：把沒有功能的題材外觀（紋理、裝飾、造型）拿掉，有功能的記號留下。剩下的版面、字與色義，還認得出是這個品牌嗎？認不出來，代表特色全在裝飾上，是扮裝。
3. **指認**：能不能用一個現成風格的名字就講完這個畫面？能，而且那個風格不是使用者指定的，重想。只有幾個表面元素像某個風格時，拿掉或減弱那幾個元素即可。

三題都要做：題材扮裝會通過第 1 題（借來的外觀本來就不適合別的題目），由第 2、3 題判斷。

## 亮點要少

- 強調的東西要少：大的元素最多兩個，對比手法不超過三種；什麼都強調等於沒強調（[NN/g](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)）。
- 亮點要讓畫面**變少或變清楚**：它取代了原本要另外放的東西，或讓某件事不必讀內文就知道。只是多加一塊內容或一圈裝飾的不算亮點。
- 亮點要有功能（標示狀態、品牌識別、引導主要行動）。
- 拿掉一件飾品：定稿前檢查有沒有兩個記號在講同一件事，有就拿掉一個。

## 現成風格（舉例，不窮盡）

下面是目前最常被直接套用的樣子。這份清單只是舉例，不完整也會過時：**避開清單上的樣子、換成清單外另一個現成風格，是同一種失敗**。判斷靠換題測試，不靠比對清單。frontend-design skill 另有一份清單，兩份都算。使用者指定了其中一種時照做。品牌一手資料裡的顏色與字型優先於清單：撞到時換掉搭配（例：拿掉米色底），不刪品牌色。

- Inter／系統字當唯一字型，紫藍漸層背景或按鈕；玻璃擬態、霓虹發光
- 米色底＋襯線標題＋赤陶橘
- 深色底配單一亮色（螢光綠、朱紅）
- 新粗野主義：粗黑框、零圓角、極粗黑體、高彩度色塊、硬陰影
- 報紙式細線與密欄
- 置中大標＋漸層光暈＋兩個按鈕的英雄區
- 內容切成一模一樣的圓角卡片，每張同樣的陰影；所有區塊同樣的留白，沒有層級
- 三欄「圖示＋標題＋一句話」特色區；表情符號當圖示；圖示粗細、風格混用。這幾條講的是裝飾性的圖示排版套路，不是說介面不該用圖示：工具型介面的導覽與操作該有圖示，見 ux-patterns.md〈圖示〉

克制本身不是問題，安靜的設計不必為了「有特色」加料。它要過的是兩件事：看得出層級（第一眼看哪裡、第一步按哪裡），看得出身份（字型、用色、用詞是這個機關或品牌的）。

## 參考庫用法

| 用途 | 去哪裡 | 怎麼用 |
|---|---|---|
| 真實產品的頁型與流程 | Mobbin（app／web，付費）、Refero（依頁型與元件分類） | 找 3 個同類產品的同一頁型，列出共同做法與差異 |
| 視覺方向 | Land-book、Recent（原 Godly）、Lapa Ninja | 只借概念與手法，不抄版面 |
| 政府／公共服務 | 日本數位廳 DADS、英國 GOV.UK Design System | 排版、表單、無障礙做法 |
| 字型搭配 | Google Fonts、Typewolf | 中文先確定黑體／明體，再配英文 |

參考只能借「為什麼有效」，寫進方向稿說明；不要複製特定網站的版面、插圖或品牌元素。

## 退件追問

使用者說「不好看」「沒感覺」「很亂」但說不出原因時，用 AskUserQuestion 一次問 1～2 題，每題給具體選項：

- 哪裡不對：資訊太多／太亂、不知道從哪裡開始、像 AI 做的（像範本）、太素／太花、太冷／太可愛、層級不清楚、字太小或太擠
- 想往哪裡推：更安靜（東西更少、預設只留主要任務）／更有溫度（暖色、明體、手繪感）／更專業（深色、黑體、網格）／更大膽（大字、強對比、不對稱）
- 有沒有一個參考網站「就是要這種感覺」

答案是「資訊太多」「不知道從哪裡開始」時，問題在資訊分層不在外觀：回第 3 步改分層表，不是換顏色。答案是「像 AI 做的」時，重做換題測試，不是換成另一個風格。

問出來後只改那一點，附前後對照截圖。
